# 接入一个新领域

这套情报引擎（Radar）跟领域是解耦的：采集 → 存储 → 打分 → LLM 解读 → 呈现这条管线不动，换领域只动"领域配置"那几处。本文把这些地方一次点清，附一个把它接到「金融」领域的走查。

底座不用碰的部分：`runner.ts` 调度、`detail.ts` 正文抓取与降级、优先级归一化算法、收件箱/看板/RAG 前端、PWA。真正跟领域绑死的是下面 8 处，其中 2 处在数据库、6 处在代码。

## 改动清单

| # | 位置 | 改什么 | 不改会怎样 |
|---|------|--------|-----------|
| 1 | `src/lib/monitor/<新源>-list.ts` + `runner.ts`（L48 按 `source.type` 分发） | 每个数据源一个抓取器，导出 `fetchXxxLatest(listUrl, limit) → {title, url, listPublishedAt}`，在 runner 里加一行 `if (t === "xxx_list") return fetchXxxLatest(...)`。多数政务/列表站结构类似，可直接复用 `generic-government-list.ts`，不必新写 | 没有新领域的数据进来 |
| 2 | `src/lib/monitor/source-meta.ts` | 来源目录：把新领域的官方源登记进去（名称、分组、说明） | 来源页仍显示旧领域目录 |
| 3 | `src/lib/monitor/content-meta.ts` | 分类体系：`CATEGORY_STYLE` 里的信号层（A/B/C/D + 落地）和主题层（`topic_*`）文案与配色，顶部注释是 category id ↔ 中文名的映射 | 卡片挂着旧领域的信号/主题标签 |
| 4 | `src/lib/monitor/priority-score.ts` → `HIGH_WEIGHT_DEPARTMENTS`（L206） | 换成新领域的主管部门/权威来源 | **新领域的核心来源被系统性少算 10 分**，排序失真（这是最容易漏、后果最隐蔽的一处） |
| 5 | `src/lib/monitor/department-meta.ts` → `DEPARTMENT_META`（L35） | 追加部门行，带别名/拼音，用户用非正式名（"发改委"）也能命中 | 搜索/筛选按部门时新来源匹配不上 |
| 6 | `src/lib/ai/content-analyzer.ts`（L105 system prompt）+ `policy-analyzer.ts` | LLM 的人设与信号释义：现在写死"人工智能与数字经济政策…工信部/网信办/发改委"。换成新领域的分析师视角 + 顶部 `SIGNAL_*` 释义映射 | LLM 仍用旧领域视角解读，答非所问 |
| 7 | `src/lib/monitor/channel-group.ts` → `CHANNEL_GROUPS`（可选） | 收件箱按栏目分组的标签 | 分组名沿用旧领域，不致命 |
| 8 | `src/lib/monitor/detail-mock.ts` / `mock.ts`（可选） | 离线/演示模式的样例文章 | demo 模式展示旧领域样例，接了真库就不影响 |

## 数据 vs 代码：两处其实不用改代码

- **关键词**存在数据库 `monitor_keywords` 表（`keywords.ts` 按 department + global 读取），换领域＝改种子数据或后台增删，不动代码。
- **数据源清单**存 `monitor_sources` 表，`runner.ts` 按 `source.type` 分发。加一个已支持类型的源，只加一行数据；只有遇到全新站点结构才需要写第 1 项的抓取器。

也就是说：**"接入新源"和"调关键词"是运营动作（改数据），"换分类/换加权/换 LLM 视角"才是改代码**。这条分界是有意的——高频调整落在数据层，代码层只在领域本身变了才动。

## 领域边界的两个数据层杠杆（2026-09 新增）

早期底座有个隐患：**入库不设主题门槛，凡是启用的源，抓到的每条都进库**。种子源又是通用政务全家桶（21 部委 519 栏目），于是农业补贴、烟草、水利这些跟当前领域无关的内容会淹没真正相关的条目。修法是加了两个**纯数据层**的杠杆，正好落在上面这条"换领域只改数据"的分界内：

1. **源的三态（`monitor_sources.enabled` + `notes` 标注）**：无关领域的源不删，而是 `enabled=false` 并标"其他行业储备"。停用即不再抓取、前台条目查询统一按 `enabled=true` 过滤（隐藏但保留）；源管理页仍显示全部，可一键重启用。→ **换领域 = 翻一下哪些源激活**，整套政府爬虫库当可复用资产留着，不是从零重建。

2. **领域主题门槛（`monitor_keywords` 里 `department_name='__domain__'` 一类词）**：与既有 `__global__` 信号词（进库后算强度分）语义分开——`__domain__` 是**入库前的白名单**，标题命中至少一个领域词才收（空表=不过滤，保持旧行为，见 `runner.ts` 的 `passesDomainGate`）。→ **换领域 = 换这一张 `__domain__` 词表**，把留下源里的行政杂务（人事/采购/时政）挡在门外。

合起来：**"换领域"从"改 6 处代码"里又剥出两件纯数据动作——激活哪些源、领域词表是什么**。这两件不碰代码，正是"通用套壳可复用"从口号变成可验证事实的地方。实测：一轮抓取扫 124 条→门槛滤掉 85 条杂务(69%)→入库的全是本领域内容。

## 走一遍：接「金融」

1. 数据源：央行、证监会、银保监的公告页多是静态列表 → 直接复用 `generic-government-list.ts`，在 `monitor_sources` 加几行 `type: "generic_list"` 的数据，无需写新抓取器。
2. `HIGH_WEIGHT_DEPARTMENTS`：换成 中国人民银行 / 证监会 / 金融监管总局 / 财政部。
3. `content-meta.ts`：信号层沿用 A/B/C/D 语义（强约束/强支持/风险/观察），主题层换成 货币政策 / 资本市场 / 银行保险 / 跨境。
4. `content-analyzer.ts`：人设改成"金融政策分析师"，信号释义改成金融口径。
5. 关键词：往 `monitor_keywords` 灌一批（利率、LPR、资本充足率、注册制…）。

前端、打分算法、抓取管线一行不动。

## 已知边界（这是 roadmap，不是缺陷）

上面 6 处代码目前是**按领域硬编码**的，还没抽成单一的 `domain config` 模块——换领域仍是"fork 仓库 + 改这 6 处"，不是"改一个配置文件"。

这是有意的取舍：只有两个实例时，抽公共配置层属于为架构而架构，收益低于成本。**已经证明的是架构与领域解耦（同一底座已跑政策、AI、音乐三个领域）；把这 6 处收敛成一份 domain config 是下一步。** 本文档就是那份 config 的"人肉版"——先标清扩展缝，再决定要不要固化成代码。
